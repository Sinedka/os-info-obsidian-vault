# IDT (Interrupt Descriptor Table)

## Что такое IDT
IDT (Interrupt Descriptor Table, таблица дескрипторов прерываний) — это структура в памяти, которую использует процессор x86/x86_64 для обработки прерываний и исключений. По сути, IDT — это таблица, в которой для каждого номера прерывания (вектора) хранится описание того, как перейти к обработчику.

Процессор обращается к IDT при любом исключении (деление на ноль, page fault и т.д.), аппаратном прерывании от контроллера прерываний, а также при выполнении инструкции `int`.

## Зачем нужна IDT
- Определяет, куда передать управление при конкретном прерывании/исключении.
- Позволяет задать разные уровни привилегий для вызова обработчиков.
- Обеспечивает механизм безопасного перехода из пользовательского режима в режим ядра.

## Расположение и загрузка
Адрес IDT хранится в специальном регистре процессора `IDTR`.
- Инструкция `lidt` загружает базовый адрес и размер таблицы.
- Инструкция `sidt` позволяет прочитать текущее значение.

В 32‑ и 64‑битных режимах структура записи отличается, но принцип одинаков.

## Формат записи (descriptor)
Каждый элемент IDT описывает один вектор. В классической реализации x86 используются записи двух основных типов:
- **Interrupt Gate** — при переходе процессор автоматически сбрасывает флаг прерываний (IF).
- **Trap Gate** — флаг IF не сбрасывается, прерывания могут оставаться включёнными.

Также встречаются Task Gate (устаревший вариант, связан с TSS).

### Основные поля (упрощённо)
- **Offset** — адрес обработчика (разбит на части).
- **Selector** — сегмент кода, в котором находится обработчик.
- **Type/Attributes** — тип шлюза, уровень привилегий (DPL), признак присутствия (P).

## Векторы прерываний
- **0–31** — исключения процессора (деление на ноль, invalid opcode, page fault и т.д.).
- **32–255** — обычно аппаратные прерывания и программные прерывания ОС.

ОС обычно переназначает (remap) аппаратные IRQ, чтобы они не конфликтовали с исключениями.

## Привилегии и безопасность
Поле DPL в записи определяет минимальный уровень привилегий, с которого разрешён вызов:
- DPL=0 — только режим ядра.
- DPL=3 — разрешён вызов из user mode (например, системные вызовы).

Это критично для системных вызовов: ОС может разрешить `int 0x80` или использовать `syscall/sysenter` в новых ABI.

## IDT в 64‑битном режиме
В x86_64 размер записи увеличен (адрес обработчика 64‑битный), но логика остаётся:
- Offset разбит на 3 части.
- Selector и атрибуты аналогичны.

## Взаимодействие с обработчиками
При срабатывании прерывания процессор:
1. Сохраняет контекст (RIP/EIP, CS, RFLAGS и иногда код ошибки).
2. При необходимости переключает стек (используется TSS/IST в x86_64).
3. Передаёт управление обработчику, указанному в IDT.

Обработчик должен корректно завершиться инструкцией `iret/iretq`.

## Связанные понятия
- **GDT** — таблица глобальных дескрипторов сегментов.
- **TSS** — структура для переключения стека и задач.
- **PIC/APIC** — контроллеры аппаратных прерываний.

## Почему это важно
IDT — центральная часть механизма обработки прерываний. Без неё ОС не сможет:
- реагировать на исключения и аппаратные события;
- реализовать системные вызовы;
- обеспечивать стабильность и безопасность исполнения кода.
